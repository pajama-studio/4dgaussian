# 4D Gaussian 学习体验：审查与重组方案

状态：以下保留原始审查与设计建议。2026-09-21 已实现独立 `/learn/` 十二课主线、每课实验、自测反馈与本机复习进度，见 [课程实现记录](zero-to-hero.md)。原方案中全局共享实验状态与公式项高亮等建议不代表全部已实现；现有 `/math/` 内容与深链接继续有效。

## 依据与当前问题

审查范围：`/math/` 的基础数学、39 组公式及推导、SH 实验、像素前向与梯度实验、源码连接；结合此前 Gaussian Inspector 的使用场景。

- 当前生成器包含 39 组公式推导、8 个数学基础主题。浏览器当前状态包含 100 个 details；1088×782 视口下文档约 32855 CSS px，SH 实验本身约 3483 CSS px。高度取决于展开状态和视口，不是固定指标。
- 导航同时列出基础、两个实验与 00–09 章节，没有明确区分学习顺序与按需查阅。全局滚动进度不代表已经理解。
- 基础课 A 一次引入向量、点积、长度、归一化、转置、外积及求和符号，缺少可操作图示和即时检验。新手仍需自己决定怎样把这些概念与 GS 联系起来。
- 大多数正文、公式、源码和自测沿纵向排列，学习者需要跨屏记住前面的变量与结果。自测展开直接给出答案，目前没有作答、针对性反馈或掌握状态。
- 浏览器实测基础正文 14px，通道图说明 11px；现有移动样式将部分正文设为 13px、通道说明设为 10px。应区分正文与元信息，提高核心内容的可读性。
- 当前互动很丰富，但常是先开放全部旋钮，再用长段文字解释。基础图、模型方向、图示相机、真实 STG 数据与教学 SH 各自需要清楚的语义边界。

这些是基于代码与页面走查的判断，尚未进行独立学习者测试。优先验证学习者能否完成任务，而非只看点击数量或页面停留时间。

## 推荐的信息架构

三个入口共用一份内容和计算逻辑，不复制三套数学实现。

| 入口 | 目的 | 默认界面 |
| --- | --- | --- |
| Learn / 引导课程 | 第一次建立完整理解 | 当前目标、一个实验、必要解释、下一步 |
| Lab / 自由实验 | 自主探索与调试 | 完整参数、对照快照、公式/数值/代码联动 |
| Reference / 公式速查 | 面试复习和实现查阅 | 搜索、完整公式、符号约定、源码、边界条件 |

数学基础作为随用随查的工具库，也保留独立复习入口。遇到协方差再补方差与矩阵，遇到训练再补导数与链式法则；不要把八个主题变成进入实验前的必修门槛。

建议导航路径：

1. 一颗 Gaussian 如何影响一个像素：先看完整故事与输出。
2. 它是什么：位置、尺度、旋转、不透明度与协方差。
3. 相机如何看见它：空间变换、投影、Jacobian 与屏幕椭圆。
4. 像素如何形成：覆盖、排序、透射率与 alpha 合成；连接传统光栅管线。
5. 颜色为何随方向变化：DC、一个非零高阶项、RGB 分通道，再逐步开放完整 SH。
6. 时间加入后发生什么：以本项目 STG-Lite 为主线，其余 4D 表示进入对比课。
7. 误差如何修改参数：loss、局部变化率、反向传播、一步更新，再区分 SGD 与 Adam。
8. 从训练到引擎：导出字段、CPU/GPU 数据布局、Rust/wgpu 调用、性能与验证。

这条教学路线先建立前向渲染的直觉，再解释训练的反向过程；部署/训练操作清单仍按数据准备→训练→导出→加载→渲染排列。

## 每一节课的固定结构

每节围绕一个可以验证的问题。建议目标为约 5–10 分钟的学习单元，实际时长须由走查确认。

1. **目标**：例如“改 R 系数，为什么 G 和 B 不变？”
2. **先猜**：给一个明确预测问题，允许跳过。
3. **动手**：默认只开放本步骤需要的控制；始终显示真实输出。
4. **解释**：先写一句结论，再展示公式。展开推导可以逐步看，也可以一次展开全部。
5. **连到代码**：点击公式项，高亮对应参数、中间值与真实源码片段。标明教学求值器与生产引擎的差别。
6. **检验**：改变条件，确认学习者能迁移理解；给针对性提示、重试与解释。
7. **继续**：明确下一节会解决什么问题；可跳过，无强制解锁。

桌面布局建议：窄课程导航 + 解释区域 + 固定可见的实验区域。课程步骤变化时更新解释和高亮，避免销毁图示或重置用户参数。代码视图可展开占用更多宽度。小屏采用单列：本步目标→图示→少量控制→解释→继续，避免将桌面三栏硬塞进去。

解释、公式和代码的不同深度应可以自由切换，但当前图示、参数和输入方向保持一致。关键前提、单位、clamp 语义不藏在高级入口里。

## 最适合先落地的两节样板课

### 样板一：向量与观察方向

- 拖动箭头端点，同时更新 (x,y,z)、长度和归一化方向。
- 切换“改变长度”和“改变方向”的例子。
- 用同一方向箭头连接到 Gaussian 的相机方向和 SH 输入。
- 先只教位置、方向、长度、归一化；点积在投影或 SH 中补充，外积在协方差中补充。
- 检验：“把 (3,4) 改成 (6,8)，长度怎样变？单位方向是否变？”

### 样板二：SH 的 RGB 独立性

- 从只有 DC 开始：转动图示、改变输入方向，区分两种操作，确认恒定颜色。
- 只启用 Y₁₀（本项目 k=2）的 R 系数，观察上下两个方向的变化。
- 在同一方向并排显示基函数值、R/G/B 三个乘法、逐项和与最终颜色。
- 请求预测：“只改 a₂R，G 会变化吗？”操作后高亮 R 路径，G/B 保持正常显示。
- 再打开 G/B 编辑、其他基函数、完整 16 项和拟合实验。
- 提供“保存当前对照 / 恢复默认 / 返回上一步”。
- 真实 STG-Lite 保存直接 RGB；教学 SH 系数不可伪装成真实数据。模型模式应始终可见。

## 学习状态与可读性

- 记录“读过 / 做过实验 / 通过检查”，与单纯滚动进度分开；自报理解与自动验证也分开。
- 继续学习恢复章节、步骤与模型参数，保留语言选择。先用本地存储，无需账户系统。
- 术语点击打开短解释或侧栏，并提供返回上下文；同时保留可键盘访问的链接。
- 推荐正文 16–18px，行高约 1.6–1.8；读数与控制标签尽量至少 14px。公式独立排版，长推导按等号的每次变化拆开，不把整串公式缩得很小。
- R/G/B 颜色继续保留，但同时用文字标记；每个公式符号与对应控制/图示的映射稳定。
- 控制与所影响的结果靠近；展示变化前后数值及差值。预设、重置、撤销比增加更多旋钮优先。
- 键盘旋转、缩放、焦点提示、减少动画偏好继续保留。主要触控按钮目标尺寸按 44px 设计；这是本项目的舒适性目标，不把它误写为 WCAG 2.2 AA 的统一最低要求。

## 实施顺序和验收

第一阶段：学习入口、课程地图、三种模式、恢复进度；把现有内容按入口呈现，保留旧 hash 深链接及打印全文。

第二阶段：以上两节样板课。确认读者能够正确预测、完成操作并解释结果，再迁移其余课，避免一次给 39 组推导套上未经验证的模板。

第三阶段：共享实验状态、公式/数值/代码高亮、对照快照、知识检查与复习清单。先完成主线，表示比较和完整推导作为可深入阅读的材料。

验收任务：

- 新访问者能找到“从哪里开始”，并说出当前一节的目标和下一步。
- 用 (3,4) 与 (6,8) 正确区分长度和方向，并说明 SH 为什么只接收单位方向。
- 修改一个 R 系数后，能预测并核对 G/B 不变；能区分图示相机与求值方向。
- 从一条公式定位实际代码，能分辨独立教学计算与引擎实现。
- 切换语言、步骤或帮助面板后，参数和学习位置不丢失。
- 390px 窄屏和键盘操作可完成上述任务；没有整页横向溢出。
