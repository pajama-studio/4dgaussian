STEP步骤 1 / 5

Run the smallest complete experiment先跑最小完整实验

Use the repository commands below. The Python exercise creates a synthetic teacher, fits five Gaussians with Adam, evaluates separate synthetic views/times and exports a PLY plus cameras. It needs Python with PyTorch and NumPy. The native Rust example needs a working wgpu adapter. This exercise is distinct from the two-Gaussian browser SGD lab.运行下方仓库命令。Python 练习创建合成教师，用 Adam 拟合五颗 Gaussian，对单独的合成视角与时间评估，并导出 PLY 和相机。需要带 PyTorch、NumPy 的 Python 环境；Rust 原生示例需要可用 wgpu 适配器。它与浏览器双 Gaussian SGD 实验不同。

STEP步骤 2 / 5

Integrate a pass, not a second engine把渲染通道接入引擎

Let the host own device, queue, camera, clock and render targets. The Gaussian pass owns model buffers and its rendering resources. Each frame evaluates visibility/order, updates per-frame camera/time and index data, then encodes a pass into the host’s command flow. The current StgPass is an integration starting point; it is not evidence of a completed integration into another engine repository.设备、队列、相机、时钟与渲染目标由主引擎管理，Gaussian 通道管理模型缓冲与自己的渲染资源。每帧求可见性和顺序，更新相机、时间与索引数据，再把渲染通道编码到主机命令流。当前 StgPass 是接入起点，不等于已经集成到另一个引擎仓库。

STEP步骤 3 / 5

Keep common math separate from backend mechanics分离通用数学与后端机制

Time decoding, coordinate contracts, SH conventions and expected pixel behavior can be shared across backends. Buffer alignment, shader language, synchronization, sorting primitives and render/compute dispatch belong to backend implementation. CUDA compute splatting and wgpu quads can implement related image formation with different scheduling. Matching outputs requires matching approximations as well as formulas.时间解码、坐标契约、SH 约定与像素预期可以跨后端共享。缓冲对齐、着色语言、同步、排序原语及渲染或计算调度由后端实现。CUDA 计算 Splat 与 wgpu 四边形可以实现相关成像，但调度方式不同。对齐输出不仅要对公式，还要对近似。

STEP步骤 4 / 5

Measure the actual bottleneck测出真正瓶颈

Record decode time, CPU visibility/sort time, upload bytes, GPU pass time, resolution and visible splat count. High overlap can dominate fragment work even with a modest point count. Timing an asynchronous API call is not GPU execution time. Use supported timestamp queries or carefully scoped measurement; avoid a blocking readback every frame.记录解码时间、CPU 可见性与排序时间、上传字节数、GPU 通道时间、分辨率与可见点数。即使点数不多，重叠严重也可能使片元工作量很大。异步 API 调用耗时不等于 GPU 执行耗时。使用受支持的时间戳或明确范围的测量，避免每帧阻塞回读。

STEP步骤 5 / 5

Debug in the same order that pixels are made沿成像顺序调试

Wrong motion: inspect normalized time and decoded coefficients. Mirrored scene: inspect camera axes and matrix conventions. Giant splats: inspect log-scale activation and covariance units. Dark colors: inspect direct RGB versus SH and premultiplied blending. Popping: inspect visibility and order changes. Low FPS: measure stages before replacing the rasterizer.运动错误查归一化时间与解码系数；镜像场景查相机轴和矩阵约定；巨大点查 log-scale 激活与协方差单位；颜色发黑查直接 RGB / SH 与预乘混合；跳变查可见性与排序变化；低帧率先分阶段测量，再决定是否替换光栅器。

PUT NUMBERS IN代入数字

A decoded 32-float row is 128 bytes. At 108,317 splats this is about 13.22 MiB. Uploading only 108,317 32-bit indices costs about 0.413 MiB per frame, rather than resending the complete records. These numbers exclude duplicate CPU copies, GPU padding, render targets and other resources.每行 32 个 float 是 128 字节，108,317 颗约占 13.22 MiB。每帧只上传同数量的 32 位索引约需 0.413 MiB，无需重传整套记录。这些数字不包含 CPU 重复副本、GPU 填充、渲染目标与其他资源。
